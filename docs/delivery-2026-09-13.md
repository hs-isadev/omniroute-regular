## Routing evidence

The available legacy history contains 134 completed routes: Groq 118 (88.06%),
Gemini 14 (10.45%), and Claude browser 2 (1.49%). The history does not record
candidate health or exclusion snapshots, so historical eligibility cannot be
reconstructed conclusively. Analysis used content-free fields only. The detailed
task-class, model, source, fallback and policy breakdown and code findings are in
[the routing report](routing-imbalance-2026-09-13.md).

Selection now balances least-dispatched eligible providers and equally ranked
models, preserving explicit priorities and pins. Limits, health, quotas,
cooldowns, concurrency and task requirements remain eligibility gates.
Content-free diagnostics explain selection, exclusion and actual fallback.

Synthetic equally eligible healthy candidates received Groq/Qwen/Kimi shares of
12/12/12 across 36 selector dispatches and 3/3/3 across nine completed fake-provider
router requests. These are regression fixtures, not live provider traffic.

## Verification and installation

- Build/typecheck passed; full suite: 183 passed.
- Final focused packet/routing suite: 15 passed, including one later-added test.
- Distribution suite: 131 passed, two skipped.
- Final extracted family package smoke passed: 2,746 files scanned, both OS
  manifests checked, temporary Windows install, browser policy validation and
  actual MCP protocol tests with a fake provider.
- Installed version: `versions/0.6.4-private.1-6c23ec5bcf45` under
  `%LOCALAPPDATA%\OmniRouteRegular`.
- Supported integration updates succeeded for Codex, Claude Code and Antigravity,
  including packaged browser adapter paths. Credentials were preserved.
- Native Linux desktop/keyring and live Antigravity behavior were not tested.

An API-only startup validator had rejected the browser-enabled configuration
before MCP tools registered. That validator is repaired. The earlier installed
runtime hotfix passed an actual MCP initialize/tools-list handshake; the final
extracted 0.6.4 package also passed MCP testing. Automatic approval review blocked
the final post-update installed-server handshake/configuration recheck because
it reported an account usage limit. That last check remains unverified and was
not retried through another execution path.

Already-open Codex sessions need reconnect/restart to discover the repaired MCP
server. At the last browser readiness check the launcher reported sign-in needed
for Z.AI, Qwen, Kimi and DeepSeek; all six browser providers were unhealthy in the
last health snapshot. No inference or historical prompt was sent for diagnosis.
