# OmniRoute Private 0.6.6-private.1

Local replacement candidate for 0.6.4-private.1 and the unshipped 0.6.5-private.1
candidate. It is not published.

## Added

- The API-key window provides five masked credential slots for every listed
  provider. Cloudflare keeps token and account ID paired within each slot.
- Each supplied slot is validated independently with a fixed harmless request.
  The completion dialog names accepted slots, rejected slots with safe reason
  codes, and the current stored slot count for each provider.
- Valid slots are encrypted independently. The legacy provider record remains
  slot 1, so existing credentials migrate without re-entry.
- API and OpenCode compatibility runtimes rotate healthy slots. Authentication
  and quota failures cool down only the affected slot before another credential
  for the same provider and free model is tried.
- Metadata-only provider diagnostics report credential counts, slot numbers and
  per-slot outcomes without response bodies or credential values.

## Fixed

- The previous vault schema used the provider ID as its only record key, so a
  second credential necessarily overwrote the first.
- The key window now shows which submitted credentials worked instead of the
  ambiguous “working keys saved” message.
- The live validator now reserves 512 output tokens. A 32-token ceiling could
  consume the entire output budget as hidden reasoning and falsely report an
  empty response; this was reproduced with Groq GPT-OSS.
- Groq's retired `qwen/qwen3.6-27b` catalog entry migrates to the current
  `qwen/qwen3.8-27b` identifier.
