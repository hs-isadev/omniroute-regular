# OmniRoute Private 0.6.5-private.1

Local replacement candidate for 0.6.4-private.1. It is not published.

## Fixed

- Provider health construction now checks providers concurrently, so one slow API
  cannot consume a shared deadline and falsely mark every later route unhealthy.
- Package verification requires the platform's bundled Node executable and the
  regular MCP entrypoint before installation or registration.
- Antigravity, Codex and Claude registrations are derived from the validated active
  version. Setup refuses incomplete runtimes; rollback repairs registrations; an
  existing verified inactive stage can be selected again during roll-forward.
- The family smoke test exercises 0.6.4 to 0.6.5 update, rollback, roll-forward,
  paths containing spaces, and initialize plus tools/list through the exact command
  written to an isolated Antigravity configuration.
- A metadata-only validator distinguishes disabled, unconfigured, policy-ineligible,
  unsupported, authentication, quota/rate-limit, timeout, endpoint, provider and
  success outcomes. It sends only the fixed synthetic prompt `Reply with OK only.`
  and never records response bodies or credentials.

task classes, capabilities, context limits, pacing, cooldown and single-call rules
are unchanged.

## Compatibility and limits

The currently installed 0.6.4-private.1 package and active version both contained
Node, and its exact registered Antigravity command completed MCP initialize and
tools/list during this investigation. The earlier missing-path launch failure could
therefore not be reproduced from the surviving files. This release closes the
verification and stale-registration paths that previously allowed setup/update
success to be reported without proving that the registered executable existed.

The archive is unsigned. Verify its accompanying SHA-256 before installation.
