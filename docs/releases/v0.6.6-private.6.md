# OmniRoute Private 0.6.6-private.6

Rebuild of the Windows/Linux family download package with stable browser
consumer auto-start paths.

## Fixed

- Windows Startup and Linux desktop auto-start entries now invoke the stable
  installed `Launch.ps1` or `Launch.sh` wrapper instead of embedding a
  version-specific `node.exe`/Node path to a superseded version folder.
- The wrapper reads `active-version.txt` on each run, verifies the active Node
  runtime and browser adapter entrypoint, and starts the shared browser session.
  This avoids stale-version paths after package updates or removal of old
  version folders.
- Setup migrates the package's recognized older browser-consumer auto-start
  entries. Unknown entries remain untouched. Missing-runtime failures now show
  an OmniRoute repair message instead of Windows' ambiguous “cannot find” dialog.

No provider keys, browser profiles, cookies, account sessions, or user data are
included. The existing free-only model routing and browser-consumer limits are
unchanged.

Setup includes only four practical coding skills—focused implementation, code
review, root-cause debugging, and change verification—and installs them for
Codex, OpenCode and Antigravity. Existing same-named skills are preserved.

package-only upload; no source branch was pushed. GitHub may show an automatically
generated source snapshot as well, but it is not the installer package. The new
release tag points to the last source commit already published on GitHub; the
