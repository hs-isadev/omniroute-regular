# OmniRoute 0.6.7

OmniRoute OpenCode now chooses the strongest configured host model that is
healthy, free, within the request's context/output limits, and capable of the
requested work. OpenRouter's curated free GPT-OSS models can participate when
the current account's model discovery confirms them as available.

Quota behavior is provider-wide: HTTP 429/402 cools that provider's models and
saved key pool, then permits failover to another eligible provider. OmniRoute
does not rotate another key or model from the limited provider to get around its
quota. Invalid-key authentication errors can still try another saved slot.

The Windows/Linux download includes the same runtime changes, updated plain-
language README, key shortcuts, skills, and optional `code.zip`. Validation uses
fixture-backed source and package tests; no live provider quota or key was used.

Windows and Linux launchers accept the `harness` action and forward it to the
bundled OmniRoute CLI (defaulting to OpenCode regular mode when no target is
given), so `omni harness opencode --mode regular` works with the packaged
launcher. Updating an existing install retains the active and one rollback
version, then removes older verified, unmodified runtime copies. Saved keys,
settings and unknown/modified files are preserved.
