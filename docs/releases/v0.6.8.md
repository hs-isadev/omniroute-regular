# OmniRoute 0.6.8

The Windows/Linux package no longer opens or autostarts consumer-browser
adapters. Setup disables those provider routes and removes only recognized
OmniRoute browser-consumer startup entries from prior installs. Unrelated startup
items and browser profiles/sign-in data are preserved; an already-running browser
is not forcibly closed.

Successful updates now retain only the active runtime and remove all older
verified, package-owned runtime copies. Provider keys, routing settings, skills,
host registrations, and other user data remain outside those version folders.
Modified or unrecognized folders are left untouched. Because prior runtimes are
removed, a previous-version rollback is not available after updating.

The package also carries the existing OmniRoute regular harness launcher,
five-slot API-key editor, Codex/OpenCode/Antigravity MCP wiring, skill bundle, and
plain-language setup guide. The source archive is included as `code.zip`.

Both Windows and Linux launchers accept `harness` and forward it to the bundled
OmniRoute CLI (default target: OpenCode regular mode), so
`omni harness opencode --mode regular` remains supported. Provider quota/rate
limits cool the affected provider and its key pool; routing may continue to a
different eligible provider, but never rotates keys to evade a quota.
