# OmniRoute 0.6.6-private.15

The five-slot API key form now protects existing credentials: a new key entered
into a filled slot is moved to the next available slot instead of replacing the
saved key. Duplicate keys are skipped and the save confirmation identifies both
the filled slot and the destination. A full provider pool refuses additional
keys without changing saved values.

Regular OmniRoute and the OpenCode adapter now reserve credential slots before
network requests, so concurrent calls rotate across multiple keys for the same
provider. A key that returns an authentication error is cooled down and the
request tries another saved key; if that provider's keys are exhausted, normal
free-only model failover can continue to another eligible provider.

The Windows and Linux **OmniRoute API Keys** shortcuts, command-line key editors,
installer bundle, README, and package smoke checks include these behaviors. No
live provider credentials were used for the tests.
