# OmniRoute 0.6.6-private.17

The existing **OmniRoute API Keys** window now shows each saved provider slot's
last-known status: Healthy, Unhealthy, Expired / rejected, or Not checked. A
typed value that has not been accepted is marked Not saved.

Use **Check saved key statuses** to run one small free-profile request per
saved slot. This is optional and may use free quota. Network or quota failures
do not relabel a key expired. A 401/403 is called “Expired / rejected” because
providers do not consistently distinguish expiry from revocation or an invalid
key.

An occupied slot has a separate **Replace saved key** control. The old key is
kept unless the replacement passes validation; if validation fails, the old
key and its prior status remain. Without that control, the established
duplicate-safe behavior still moves a new key to the next empty slot.

Windows and Linux setup windows remain in the same flow. Credentials are not
included in the package; only non-secret status metadata is kept beside the
local vault and associated with the credential slot's creation time.

Fixture-only tests cover accepted and rejected replacements, status persistence,
transient failures, status-output redaction, both setup forms, and Windows GUI
smoke checks. No live API keys were tested for this release.
