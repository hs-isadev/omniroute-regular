# OmniRoute provider capacity and limit notes

Checked against provider documentation on 2026-09-05. A number in the OmniRoute catalog is a conservative routing cap, not a promise that a browser account or API key has that entitlement. `Variable` means the provider publishes a model/account/plan-dependent limit rather than one stable number. `Unknown` means no reliable current official number was found; it must not be inferred from a related API product.

## Recommendations for large tasks

- **Best model quality:** among models exposed by the full base catalog, `gpt-5.6-sol` is the documented flagship for complex reasoning/coding, but it requires paid OpenAI API access and is intentionally disabled in the private free-only setup. Anthropic's current top Claude APIs are also paid and not part of the strict free ladder.
- **Largest documented context:** the cataloged OpenAI GPT-5.6 family has 1.05M context. Gemini Flash entries are approximately 1M. These are architectural limits, not a guarantee of free quota or practical ability to send a million-token request.
- **Best practical free large-task choice in this package:** start with Groq `openai/gpt-oss-120b` for quality and speed when the prompt fits the account's token-throughput ceiling. For a longer input, Gemini Flash has the largest configured free-tier context, but its exact daily/rate entitlement is account/model/region dependent. Cerebras GPT-OSS 120B is a useful fallback with a documented free daily token budget. Browser consumers are intentionally capped to small tasks and should not be chosen for large repository-wide work.
- **Highest practical free quota:** there is no universal winner. Kilo publishes 200 free requests/hour but rotates underlying models; Cerebras publishes up to 1M tokens/day for several free models; Groq publishes 1,000 requests/day and 200K tokens/day for GPT-OSS/Qwen; Gemini shows the exact current quota in AI Studio. Prompt size often makes token quotas bind before request counts.

## Shared browser-session constraints

All six browser adapters use one local profile (`browser-consumer-profile`) and one loopback CDP endpoint (`127.0.0.1:47842`). The package contains neither the profile nor any session material. The user signs in manually after installation. Browser UI drift, sign-out, account limits, CAPTCHAs, service unavailability, and rate limits are returned as failures so the provider ladder can continue. The adapters do not bypass these controls.

The six browser models advertise `none` and `high` reasoning, and normal browser-consumer routing defaults to `high`. A `high` request clicks the provider's visible Thinking/Extended Thinking/DeepThink/Reasoning control before submission. This is a local UI capability, not a claim that every account or model includes the feature; absence of the control is a retryable provider failure.
